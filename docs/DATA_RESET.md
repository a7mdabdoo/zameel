# دليل مسح البيانات قبل إطلاق النسخة التجريبية (Pilot Data Reset)

نظراً لأن النسخة التجريبية (Pilot) لم تبدأ بعد، ولا توجد بيانات إنتاجية حقيقية، يتم مسح وتطهير المجموعات التالية في Cloud Firestore لضمان التوافق التام مع قواعد الأمان الجديدة:

---

## 1. مجموعة الرسائل العامة (Top-level `/messages`)
- **السبب:** تم نقل المحادثات كلياً لتصبح مجموعة فرعية خاصة ومحمية داخل كل جلسة (`/sessions/{sessionId}/messages/{messageId}`)، وحذف قواعد الوصول للمجموعة العامة الجذرية لمنع تسريب الرسائل بين الطلاب.
- **الإجراء:** مسح أي مستندات موجودة في Root Collection المسماة `messages`.

---

## 2. مجموعة أسماء المستخدمين (`/usernames`)
- **السبب:** ميزة حجز أسماء المستخدمين تم التحقق منها والتأكد من عدم استخدامها في الواجهات أو الكود، وتمت إزالة قواعدها بالكامل لمنع أي قراءة عامة للبيانات.
- **الإجراء:** مسح أي مستندات موجودة في Root Collection المسماة `usernames`.

---

## 3. حماية خصوصية الطلاب في مجموعة المستخدمين (`/users`)
- **السبب:** لمنع سحب بيانات الطلاب أو استكشاف هوياتهم بالجملة، تم إيقاف عملية الـ `list` (`allow list: if false`) مع الإبقاء فقط على جلب مستند واحد مسجل (`allow get: if isAuthenticated()`).
- **إزالة البريد الإلكتروني:** تم التوقف نهائياً عن تخزين حقل `email` في مستندات Firestore، لأن البريد محفوظ ومحمٍ بشكل مستقل داخل Firebase Authentication ويصل إليه صاحبه فقط عبر `currentUser.email`.
- **نزاهة التقييم:** استبدال حقل `teacherRating` بحقلين تراكميين (`ratingSum` و `ratingCount`) يبدآن بصفر عند التسجيل، وتقوم الواجهة بحساب المتوسط مشتقاً.
- **الإجراء:** مسح أي مستندات قديمة أو تحديث المستندات التجريبية لتتوافق مع الهيكل الجديد (حذف `email`، تصفير `ratingSum` و `ratingCount`).

---

## 4. مجموعة عروض الشرح (`/offers`)
- **السبب:** حظر تخزين أي رابط اجتماع (`meetingUrl` / `meetingLink`) داخل عروض الشرح العامة لحماية خصوصية المعلم، وإلزامية تحديد `mode` ('online' أو 'in_person') مع حصر `durationMinutes` في {30, 60}.
- **الإجراء:** مسح مستندات العروض التجريبية القديمة التي تحتوي على روابط أو قيم غير متوافقة.

---

## 5. مجموعة الجلسات والضمان المالي (`/sessions`)
- **السبب:** حظر وضع تقييم افتراضي عند الحجز (`rating: null` حتى الإتمام)، وإضافة `mode` وتخزين `meetingUrl` داخل الجلسة فقط بعد الحجز من قِبل المعلم.
- **الإجراء:** مسح مستندات الجلسات التجريبية السابقة.

---

## 6. دفتر الأستاذ وحركات المحفظة (`/transactions`)
- **السبب:** اعتماد معرّفات حتمية ثابتة تمنع التكرار بصيغة `${sessionId}_${kind}` حيث `kind` ينتمي إلى `['booking', 'release', 'refund', 'compensation']`.
- **الإجراء:** مسح كافة القيود القديمة ذات المعرفات العشوائية أو القائمة على الطوابع الزمنية.

---

## أمر نشر قواعد الحماية المحدثة:
```bash
firebase deploy --only firestore:rules
```
> **ملاحظة:** ملف `firestore.rules` الموجود في المستودع لا يصبح نافذاً على مشروع Firebase حتى يتم نشر هذا الأمر بنجاح.
